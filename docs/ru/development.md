# Разработка

Это руководство знакомит со структурой исходного кода Kyanite и процессом сборки. Точные команды сборки и версии зависимостей определяет workflow GitHub Actions — это основной источник сведений.

## Процесс сборки

Сборка описана в файле:

```text
.github/workflows/build-rootfs.yml
```

Целевые платформы:

- `aarch64-unknown-linux-musl`
- `x86_64-unknown-linux-musl`

В общих чертах workflow выполняет следующее:

1. Вычисляет версию командой `git describe --tags --always`.
2. Собирает Kyanite init и `kpkg` с помощью Cargo.
3. Собирает Brush и uutils coreutils для целей musl.
4. Собирает корневую файловую систему.
5. Добавляет библиотеки времени выполнения и вспомогательные пакеты.
6. Применяет `rootfs-overlay/`.
7. Создаёт манифест базы.
8. Создаёт сжатый архив и контрольную сумму SHA256.
9. Подписывает контрольную сумму в релизных сборках.

## Требования для сборки

Сейчас в документации указаны следующие локальные требования:

- Набор инструментов Rust (toolchain)
- Необходимые цели Rust для musl
- `musl-tools`
- `gcc-aarch64-linux-gnu` для кросс-компиляции под aarch64

Проверьте workflow: для текущей сборки могут понадобиться дополнительные инструменты или пакеты.

## Оверлей корневой файловой системы

Каталог `rootfs-overlay/` содержит файлы, которые копируются в создаваемую корневую файловую систему, включая файлы конфигурации и окружения оболочки.

При изменении оверлея проверяйте пути к файлам, права доступа и то, как изменения взаимодействуют с манифестом базы и механизмом обновления.

## Тестирование изменений

Для проверки изменений используйте одноразовую корневую файловую систему.

Если вы работаете над менеджером пакетов, протестируйте соответствующие сценарии установки, обновления, удаления, восстановления, настройки и аудита. Если вы работаете над обновлениями базы, протестируйте как неизменённые файлы, так и файлы, изменённые пользователем.

## Метки версий

Сборки используют `git describe --tags --always`. Коммит после тега релиза может получить метку вида `v0.1.0-3-g1a2b3c4`. Если тега нет, версией может быть хеш коммита.

Для автоматических обновлений базы подходят только теги релизов вида `vX.Y.Z`.
