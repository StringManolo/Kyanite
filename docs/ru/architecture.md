# Архитектура

Kyanite — минимальная корневая файловая система Linux, построенная вокруг небольшого набора основных компонентов на Rust и Debian-совместимой среды пакетов.

## Обзор системы

Предустановленные компоненты на Rust статически скомпонованы с musl:

- Kyanite init
- `kpkg`
- Brush
- uutils coreutils

В корневую файловую систему также входит среда выполнения glibc для динамически скомпонованных пакетов Debian.

## Последовательность запуска

Базовый порядок запуска такой:

1. Загрузчик (launcher) входит в корневую файловую систему, обычно с помощью PRoot.
2. Загрузчик вызывает `/bin/sh`.
3. `/bin/sh` указывает на `/sbin/init`.
4. Kyanite init настраивает терминал и запускает Brush как login-оболочку.
5. Init подбирает осиротевшие процессы и завершается, когда завершается оболочка.

Init работает как PID 1 внутри окружения Kyanite.

## Основные компоненты

| Компонент | Ответственность |
| --- | --- |
| `kyanite-init` | PID 1, запуск оболочки, управление терминалом и заданиями, подбор осиротевших процессов |
| Brush | Интерактивная оболочка |
| uutils coreutils | Стандартные утилиты командной строки |
| `kpkg` | Индексы пакетов, разрешение зависимостей, установка пакетов и обновление базы |
| Среда выполнения glibc | Поддержка времени выполнения для пакетов Debian |
| `vim-tiny` | Минимальный vi-совместимый редактор |

## musl и glibc

Kyanite использует musl для своих статически скомпонованных инструментов на Rust. Благодаря этому основные утилиты не зависят от среды выполнения glibc.

В rootfs также входит glibc, чтобы могли работать пакеты из репозиториев Debian. Так компактная база сочетается с доступом к экосистеме пакетов Debian.

## Установка пакетов

`kpkg` скачивает пакеты Debian, проверяет метаданные репозитория и хеши пакетов, разрешает зависимости и распаковывает пакеты в целевой корень.

Настройка пакетов выполняется с помощью декларативных хуков Kyanite. См. [Хуки пакетов](package-hooks.md).

## Обновление базы

Обновления базы Kyanite отделены от обычных обновлений пакетов Debian. Подходящие релизы на GitHub содержат файлы и манифест, необходимые для обновления базы с сохранением локально изменённых файлов.

См. [Релизы](releases.md) и [обновление базы через kpkg](kpkg.md#updating-the-kyanite-base).

## Модель выполнения

Сейчас Kyanite распространяется как корневая файловая система и использует ядро хоста через среду выполнения. Вопросы платформ и изоляции рассмотрены в разделах [Известные ограничения](limitations.md) и [SECURITY.md](../../SECURITY.md) (на английском).
