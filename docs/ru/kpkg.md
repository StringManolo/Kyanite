# kpkg

`kpkg` — менеджер пакетов Kyanite. Он предоставляет интерфейс командной строки в стиле apk, но устанавливает пакеты из репозиториев Debian. Также есть режим, совместимый с apt.

## Быстрый старт

```sh
kpkg update
kpkg search curl
kpkg add curl
kpkg info curl
```

## Команды

| Команда | Описание |
| --- | --- |
| `kpkg update` | Загружает и проверяет индексы пакетов; проверяет наличие обновления базы Kyanite |
| `kpkg search <термин>` | Ищет по именам и описаниям пакетов |
| `kpkg add <пакет>...` | Устанавливает пакеты и их зависимости |
| `kpkg del <пакет>...` | Удаляет пакеты |
| `kpkg purge <пакет>...` | Удаляет пакеты вместе с изменёнными файлами конфигурации |
| `kpkg autoremove` | Удаляет зависимости, которые больше не нужны |
| `kpkg upgrade` | Применяет ожидающее обновление базы Kyanite и обновляет установленные пакеты |
| `kpkg fix <пакет>...` | Переустанавливает пакеты для восстановления |
| `kpkg info [пакет]` | Показывает информацию о пакете |
| `kpkg list [шаблон]` | Показывает список доступных пакетов |
| `kpkg policy <пакет>...` | Показывает установленную и кандидатную версии |
| `kpkg configure [пакет]...` | Повторно запускает хуки настройки пакетов |
| `kpkg audit` | Сверяет установленные файлы с записанными суммами SHA256 |
| `kpkg cache clean` | Удаляет кешированные архивы пакетов |
| `kpkg cache size` | Показывает использование кеша |
| `kpkg base` | Показывает версию базы Kyanite и сведения об ожидающем обновлении |

`kpkg info` поддерживает дополнительные запросы о файлах и зависимостях:

- `-L`: список файлов
- `-W`: показать, какому пакету принадлежит путь
- `-R`: показать зависимости
- `-r`: показать обратные зависимости

Точный синтаксис, доступный в вашей сборке, можно узнать так:

```sh
kpkg --help
```

## Режим, совместимый с APT

В Kyanite `apt`, `apt-get` и `apt-cache` — символические ссылки на `kpkg`.

Если программа вызвана под одним из этих имён или с `KPKG_SYNTAX=apt`, она показывает справку в стиле apt и запрашивает подтверждение перед внесением изменений. Используйте `-y`, чтобы пропустить подтверждение.

```sh
apt update
apt install curl
apt remove curl
apt autoremove
apt list --installed
apt show curl
```

Псевдоним оболочки, например `alias apt=kpkg`, не меняет имя исполняемого файла. Чтобы включить режим apt через псевдоним, используйте:

```sh
alias apt='KPKG_SYNTAX=apt kpkg'
```

## Параметры

| Параметр | Описание |
| --- | --- |
| `-s`, `--simulate` | Показать запланированные действия, ничего не изменяя |
| `-f`, `--force` | Перезаписывать файлы без владельца или чужие файлы и игнорировать обратные зависимости |
| `-y`, `--yes` | Пропускать запросы подтверждения в режиме apt |
| `--root <каталог>` | Работать с другим корнем; по умолчанию `/` |
| `--arch <архитектура>` | Задать архитектуру Debian |
| `--mirror <url>` | Задать зеркало репозитория Debian |
| `--security-mirror <url>` | Задать зеркало репозитория безопасности Debian |
| `--suite <имя>` | Задать набор (suite) Debian; по умолчанию `stable` |
| `--keyring <файл>` | Использовать указанную связку ключей OpenPGP |
| `--no-security` | Отключить репозиторий `<suite>-security` |

## Репозитории и выбор пакетов

Индекс пакетов строится из Debian `stable`, `stable-updates` и `stable-security`. Для каждого пакета `kpkg` выбирает самую высокую доступную версию.

Метаданные репозитория проверяются с помощью OpenPGP. Загруженные пакеты перед записью в конечное место проверяются по размеру и SHA256 в соответствии с подписанным индексом.

Разрешение зависимостей поддерживает:

- `Pre-Depends`
- `Depends`, включая альтернативы (`a | b`) и ограничения версий
- Виртуальные пакеты через `Provides`
- `Conflicts` и `Breaks`

Сравнение версий выполняется по алгоритму dpkg.

## Настройка пакетов

Для настройки пакетов Kyanite использует декларативные хуки. О расположении хуков, поддерживаемых действиях и заметках для разработчиков читайте в [руководстве по хукам пакетов](package-hooks.md).

## Состояние пакетов и кеш

Состояние менеджера пакетов хранится в `/var/lib/kpkg`. Загруженные файлы `.deb` кешируются в `/var/cache/kpkg/pkgs`.

Пакеты, входящие в базовую корневую файловую систему, перечислены в `/etc/kpkg/assume-installed`, чтобы `kpkg` не устанавливал их повторно.

## Обновление базы Kyanite

`kpkg update` проверяет последний подходящий релиз Kyanite на GitHub. `kpkg upgrade` применяет ожидающее обновление базы, а также обновляет установленные пакеты.

Учитываются только теги релизов вида `vX.Y.Z`. Сборки для разработки, обозначенные хешем коммита или выводом `git describe`, не подходят для автоматических обновлений базы.

Программа обновления проверяет подпись релиза и контрольную сумму SHA256, распаковывает файлы во временный каталог и применяет их по манифесту. Локально изменённые файлы сохраняются; новая версия сохраняется рядом с ними с суффиксом `.kyanite-new`.

Файл `CHANGELOG` релиза описывает операции, необходимые для изменений, которые нельзя выразить обычными обновлениями файлов.
