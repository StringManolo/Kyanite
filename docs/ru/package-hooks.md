# Хуки пакетов

Для настройки пакетов Kyanite использует декларативные хуки вместо выполнения скриптов сопровождающих пакетов Debian.

Хуки описывают ограниченный набор операций, которые `kpkg` может выполнять внутри целевой корневой файловой системы. Они также могут добавлять или игнорировать зависимости пакетов.

## Расположение хуков

Хуки, поставляемые с системой, хранятся в:

```text
/usr/share/kpkg/hooks/<пакет>.hook
```

Локальные переопределения хуков хранятся в:

```text
/etc/kpkg/hooks.d/
```

## Поддерживаемые действия

Сейчас механизм хуков предоставляет закрытый набор действий:

- `mkdir`
- `symlink`
- `link-default`
- `copy-default`
- `remove`
- `chmod`
- `builtin`

Хуки также могут добавлять или игнорировать зависимости.

Эти действия декларативны; хук не является произвольным shell-скриптом.

## Пример: сертификаты CA

Пакет `ca-certificates` использует встроенную функциональность Kyanite для пересборки файла:

```text
/etc/ssl/certs/ca-certificates.crt
```

Хук `curl` добавляет зависимость от `ca-certificates`, поэтому набор сертификатов доступен при установке curl.

## Повторный запуск хуков

Запустить хуки настройки для установленных пакетов можно так:

```sh
kpkg configure
```

Чтобы настроить конкретные пакеты:

```sh
kpkg configure curl ca-certificates
```

## Разработка хука

При добавлении хука сначала определите, какие настройки выполняют скрипты сопровождающих Debian для этого пакета. Решите, какие из них нужны в Kyanite, и выразите их с помощью поддерживаемых действий хуков или существующего встроенного `builtin`.

Полезный цикл тестирования включает:

1. Установку пакета в чистый rootfs.
2. Проверку получившихся файлов и конфигурации.
3. Повторный запуск `kpkg configure`.
4. Удаление пакета и проверку того, как выполняется очистка.
5. Проверку зависимостей, которые добавляет хук.

Точную грамматику смотрите в примерах хуков и реализации в исходном коде. В этом руководстве перечислены семейства действий, но синтаксис парсера не определяется.
